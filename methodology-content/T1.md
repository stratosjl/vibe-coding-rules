## What T1 is

One session. One concrete deliverable. Recoverable mistakes only. Multi-file work allowed but no multi-session continuity required. The R3 academic-literature six-item "minimum viable practice" floor lives at T1, not below T0 (D-MET-6). Full canonical: the canonical methodology specification v4.1 §2 T1.

## Cumulative requirements

**Inherited from T0 (always-on):** humanized-text skill, English and Greek alike. No em-dashes. No banned AI vocabulary.

**Added at T1 (cowork v2.1 execution rules, distributed):**

1. **Plan first** (cowork rule 1). One-line statement of what you are about to do before doing it. If the task changes direction mid-execution, stop and revise the plan in writing before continuing.
2. **Verify with evidence** (rule 4). If you claim something works, show the output: build result, command exit code, lint pass, file diff. Never claim success without evidence.
3. **Confirmation gate for irreversible actions** (rule 5). Pause before any deletion, force-push, deploy, external send, dropped table, or removed dependency.
4. **Capture lessons inline.** Note correction patterns in the chat itself; no separate decisions file at T1.
5. **Negative scope at end** (rule 8). If the work touches anything reusable, close with one sentence on what you deliberately did NOT do.
6. **Demand elegance, reject workarounds** (added v0.2.0; closes OBS-MET-O canonical-richer-than-slice gap). For any output that will be seen externally or used as a final deliverable, ask: "is there a cleaner approach?" If the current draft feels like a workaround, it probably is. Skip this check for quick internal notes or scratch drafts where speed is the point.

T1 has no `decisions.md`, no `open-issues.md`, no `handovers/`, no closing matrix, no audit-pass, no opening-prompt-for-next-session. T1 is single-session by definition.
