## 1.10.3 - 2026-05-21

Documents the macOS gap in the v1.10.2 cross-runtime `/tmp` fix (OBS-MET-AK). The v1.10.2 entry stated "On Linux and macOS `tempfile.gettempdir()` returns `/tmp`; behaviour is unchanged", which was accurate on Linux but inaccurate on macOS. Apple's per-user `TMPDIR` env var defaults to `/var/folders/<x>/<y>/T/`, so `tempfile.gettempdir()` returns that path while `bin/anchor-rewrite.sh` still reads literal `/tmp`. The writer/reader divergence that v1.10.2 closed on Windows is therefore still present on macOS. The maintainer is not currently developing on macOS and has not had a session to reproduce, instrument, or verify a fix against; the gap is intentionally documented rather than scope-crept this cycle. Patch-class semver: docs plus one inline code comment plus lockstep version bump. No runtime behaviour change.

What changed:

- **`README.md`: new `## Platform coverage notes` section.** Documents the OBS-MET-AK macOS gap explicitly: the v1.10.2 fix is complete on Linux and Windows but incomplete on macOS. Names the two closure paths a future macOS-development cycle could take: (a) extend `bin/anchor-rewrite.sh` to resolve the tempdir via `python -c 'import tempfile; print(tempfile.gettempdir())'` rather than literal `/tmp`. Lowest-risk patch-class change; restores parity with the writer on all three OSes. (b) Coordinate on a single tempdir convention across both runtimes (XDG-style `~/.cache/vc-roe/anchors/` on Linux, `~/Library/Caches/vc-roe/anchors/` on macOS, `%LOCALAPPDATA%\vc-roe\anchors\` on Windows). Cleaner refactor; touches both Python and bash; minor-class change. Option (a) is the natural next ship cycle; option (b) stays a parking-lot item. Section also lists the operator-side workaround for anyone hitting `No session-scoped anchor resolvable` on macOS: set `TMPDIR=/tmp` in the environment that launches Claude Code before the first SessionStart fires, which forces `tempfile.gettempdir()` to return `/tmp` and re-establishes parity with the bash reader.
- **`hooks/session-start.py`: OBS-MET-AK comment extended.** The single-line annotation at the `ANCHOR_DIR` declaration (line 78) now references the README "Platform coverage notes" section so contributors landing on the canonical fix site find the macOS gap from the code surface without having to read the CHANGELOG. The other three hooks (`user-prompt-submit.py`, `post-tool-use.py`, `stop.py`) retain their single-line OBS-MET-AK annotations unchanged; one referenced extension at the canonical SessionStart site is sufficient, and repeating the README pointer at four sites would be redundant noise.

## 1.10.2 - 2026-05-19

Closes a Windows-specific writer/reader divergence between the Python hooks (which write the per-session heartbeat anchor + UPS marker files via `Path("/tmp")`) and `bin/anchor-rewrite.sh` (which reads the same files from git-bash where `/tmp` is mapped via the MSYS mount table). On Linux and macOS the two paths collapse to the same directory; on Windows they point at different physical locations — Python's `Path("/tmp")` resolves drive-relatively to `C:\tmp\`, while git-bash `/tmp` resolves to `%TEMP%` = `<user>\AppData\Local\Temp\`. The mismatch made the anchor-rewrite resolver return `No session-scoped anchor resolvable; v0.1.7+ hooks may not be installed; manual heartbeat discipline applies` on any Windows session that had v0.1.7+ hooks installed correctly — Layer 1 marker-file lookup, Layer 2 transcript-derived `session_id` lookup, and Layer 3 size tie-break all silently failed because the reader looked in the wrong directory. Patch-class semver: changes the `ANCHOR_DIR` constructor in four hook files plus three inline `Path("/tmp")` sites; adds `import tempfile`; no schema, no public-contract surface, no methodology-content change. Captured as **OBS-MET-AK** (cross-runtime `/tmp` interpretation divergence between Python `Path("/tmp")` and git-bash `/tmp`) — twin to OBS-MET-AJ on the cwd-encoding axis, sibling on the path-resolution axis. The OBS-MET-AK marker is grep-discoverable in the code surface at every fix site so future contributors can find this entry from the code.

What changed:

- **`hooks/session-start.py`, `hooks/user-prompt-submit.py`, `hooks/post-tool-use.py`, `hooks/stop.py` — uniform `tempfile.gettempdir()` swap.** Each file replaces `ANCHOR_DIR = Path("/tmp")` with `ANCHOR_DIR = Path(tempfile.gettempdir())` and adds `import tempfile` to the stdlib imports. Three of the four files also had one inline `Path("/tmp")` site at a marker-file write or read (UPS line 89 writing the current-session marker; PTU line 162 reading it for the cross-process marker-mismatch diagnostic; Stop line 189 reading it for the same diagnostic) — each refactored to reference the module-top `ANCHOR_DIR` constant rather than reconstructing `Path("/tmp")` inline. This is the constant-extraction refactor: a single source-of-truth tempdir per hook file rather than per-site inline swaps, so any future hook contributor cannot reintroduce the divergence by copying the inline form. All seven fix sites in the four hooks are annotated with `# OBS-MET-AK`. On Linux and macOS `tempfile.gettempdir()` returns `/tmp`; behaviour is unchanged. On Windows it returns `%TEMP%`, which is the same directory git-bash sees via `/tmp` through the MSYS mount table; the writer and reader now agree.
- **`bin/anchor-rewrite.sh` unchanged.** All five `/tmp` references at lines 56, 59, 60, 75, 83 remain literal `/tmp`. Under git-bash on Windows the MSYS mount table resolves `/tmp` to `%TEMP%`; on Linux and macOS `/tmp` resolves natively. The Python-side fix above brings the writer to the same resolved directory as this reader on every platform; no script-side change needed.
- **`test-heartbeat.py` swap + Windows-portable subprocess invocation.** Line 29's `ANCHOR_DIR = Path("/tmp")` mirrored the same bug at the test-harness level; swapped to `Path(tempfile.gettempdir())` for parity with the hooks (one `# OBS-MET-AK` annotation). Lines 106 and 125 hardcoded the subprocess invocation as `"python3"`, which on Windows resolves to the Microsoft Store app-execution alias stub and silently exits 9009 — both invocations now use `sys.executable` so the test harness runs against whichever Python is currently executing the suite. Pre-fix Windows baseline: 6 / 10 PASS. Post-fix Windows baseline: 10 / 10 PASS (verified at this ship). No new test cases; same coverage, now portable to Windows.
- **`hooks/session-end.py` unchanged behaviour, `ROUTINE_VERSION` bump only.** SessionEnd had no `/tmp` references; the lockstep version bump preserves the v1.10.1 convention of single-source-of-truth across all five hooks.
- **`ROUTINE_VERSION` bumped to `1.10.2`** across all five hooks (`session-start.py`, `user-prompt-submit.py`, `post-tool-use.py`, `stop.py`, `session-end.py`); `HARNESS_VERSION` in `bin/publish-audit-combined.sh` bumped to `1.10.2` in lockstep; `.claude-plugin/plugin.json` `version` field bumped to match. Seven version constants total.

What this does NOT change: pre-push DENY/WARN pattern set in `bin/audit-patterns.sh`; the combined-audit harness wiring (`publish-audit.sh` / `publish-audit-state.sh` / `gitleaks` head + history / `test-audit-patterns.py` / inline credential heuristics — only the harness banner version string changes); the `SessionStart` `additionalContext` shape; chat-claim primitive (v1.10.0 schema unchanged); writer-lease ledger semantics; heartbeat-cadence logic; tier-detection precedence; any methodology-content slice (`T0..T4.md` byte-identical to v1.10.1); `detection-rules.json`; `README.md`; `CONTRIBUTING.md`; the operational runbook; the compliance trace; the public-contract surface (`.claude-plugin/plugin.json` schema unchanged — only the version value bumped). The v1.10.1 slash-command resolver fix is untouched; the v1.10.0 chat-claim Layer 2 surfaces are byte-identical.

Operator-side action required to pick up v1.10.2:

1. `claude plugin update vc-roe@vibe-coding-rules` writes the new files; close every Claude Code window/process and reopen so the in-memory hook snapshot is refreshed. The next session-open hook log entry will read `routine_version: "1.10.2"`.
2. No re-install of `.githooks/pre-push` or `.githooks/post-*` needed; the hooks continue to invoke `bin/publish-audit-combined.sh` and now report `combined-audit harness v1.10.2 starting` in the banner.
3. On Windows, any stale anchor files at `C:\tmp\claude-methodology-anchor-*` and `C:\tmp\claude-methodology-current-session-*` from pre-v1.10.2 sessions can be safely deleted; new traffic goes to `%TEMP%`. Linux and macOS see no on-disk relocation — `tempfile.gettempdir()` returns `/tmp` on both, so the file paths are byte-identical to v1.10.1.

Why now: the divergence was surfaced during a Windows session that ran `bash bin/anchor-rewrite.sh T4` post-elevation and observed the script reporting "No session-scoped anchor resolvable" despite the marker files being present in the Python writer's `C:\tmp\` location. Direct verification on that machine: 32 anchor files + 12 current-session marker files at `C:\tmp\` accumulated over a 12-day soak; zero such files at `%TEMP%`. Without the fix, every Windows session with v0.1.7+ hooks installed correctly silently falls back to manual heartbeat discipline at T2+ — the structural heartbeat enforcement the hooks were designed to provide is invisibly disabled. The pre-fix `test-heartbeat.py` run on Windows reported 6 / 10 cases failing for the same reason (3 heartbeat-fail cases pointed the test fixture at `gettempdir()` but the hook read from `Path("/tmp")` = `C:\tmp\`; 3 silent-stop cases failed at the `"python3"` invocation). Patch-class fix; no behaviour change on Linux or macOS; one ship cycle.

## 1.10.0 - 2026-05-12

Ships `F-63-01` Layer 2 (chat-claim reader/writer split with audit-trail-pinned writer-lease) per the s68 OPEN primary-mandate option A. Closes the F-63-01 read-only-investigation pain pattern that v1.9.0 left open: two chats can now hold a reader claim on the same project simultaneously, and writer-promotion happens post-hoc via PostToolUse on first imminent write rather than at SessionStart. Also side-closes `OBS-vcroe-contributing-doc-dispatcher-drift-01` by documenting the v1.9.1 post-* dispatcher fire-through in `CONTRIBUTING.md`. Minor-class semver because `chat-claim.json` gains five additive schema fields, PostToolUse gains a new responsibility, and Stop gains an idle-demote check; no breaking change — legacy v1.3.0..v1.9.x claims (no `mode` field) preserve exclusive-claim semantics via the `legacy-skip` path.

What changed:

- **`hooks/session-start.py` schema + acquire-reader extension (F-63-01 Layer 2).** `chat-claim.json` schema gains `mode` ("reader" | "writer"), `writer_session_id` (str or null), `writer_acquired_ts` (int or null), `writer_last_mutation_ts` (int or null), and `writer_idle_demote_seconds` (int, default 1800 s = 30 min per s68 OPEN Q2 operator decision). `write_claim()` signature gains the five new params with safe defaults; payload writes all 11 fields total. `evaluate_claim()` gains a new return action `reader-coexist`: when the existing claim is `mode=reader` and the liveness probe didn't auto-orphan and it's within TTL, the new SessionStart coexists as an implicit-reader without overwriting the existing reader claim. Multiple alive-reader chats on the same project is the new allowed shape. SessionStart `main()` integration treats `reader-coexist` as a no-write path (no banner, no overwrite). Legacy claims (no `mode` field) and `mode=writer` claims still hit the existing refuse path; exclusive-claim semantics preserved for the v1.3.0..v1.9.x compat surface.
- **`hooks/post-tool-use.py` writer-promotion + ledger (F-63-01 Layer 2).** New `handle_writer_promotion()` orchestrator runs on every PostToolUse fire (T-agnostic; chat-claim semantics are not tier-gated). `detect_write()` identifies imminent writes via two paths: (a) `tool_name in {Edit, Write, MultiEdit, NotebookEdit}` + `tool_input.file_path` matching `WATCHED_PATH_RE` (the regulator-presentable surface per `open-issues.md` § F-63-01 Layer 2 scope: `handovers/`, `decisions.md`, `open-issues.md`, `hooks/[^/]+\.(py|json)$`, `bin/[^/]+\.(sh|py)$`, `.claude-plugin/plugin.json`, `.githooks/`, `CHANGELOG.md`, `methodology-content/T[0-4]\.md`); (b) `tool_name == "Bash"` + `tool_input.command` matching `GIT_MUTATION_RE` (commit, push, tag, merge, rebase, reset, cherry-pick, revert, filter-repo, filter-branch, am, stash apply/pop/drop/push, worktree add/remove/prune/move, switch, checkout, restore, clean, update-ref, symbolic-ref, notes add/edit/remove/append/copy). Read-only git invocations (`status`, `log`, `diff`, `show`, `rev-parse`, `branch -l`) are intentionally NOT in the regex. `evaluate_writer_promotion()` decides one of five actions: `promote` (mode=reader OR mode=writer-dead-other → take writer lease), `refresh` (mode=writer same-session → refresh `writer_last_mutation_ts`), `conflict` (mode=writer alive-other-session → emit `CHAT-CLAIM WRITER CONFLICT` banner via `additionalContext` + append conflict row to ledger, do NOT overwrite), `legacy-skip` (no `mode` field → preserve v1.9.x exclusive semantics), `no-claim` (file absent → silent no-op; PostToolUse does not cold-start writer claims). Same-host liveness probe (boot_id mismatch, pid_starttime mismatch, dead PID) mirrors `session-start.py` byte-for-byte; cross-host claims fall through to the conflict path (cannot probe remotely). PostToolUse main() integration prepends the writer-conflict banner to any heartbeat `additionalContext` so both surface in a single hook emission. Worktree bypass (mirror of v1.9.0 Layer 4 check) short-circuits the entire writer-promotion block when cwd is inside a linked git worktree.
- **Writer-lease ledger.** New append-only JSONL file at `~/.claude/projects/<cwd-dashed>/writer-lease.jsonl` (per s68 OPEN Q4 operator decision — sibling to `chat-claim.json` in the same local project dir, not in the OneDrive sync path). Every PostToolUse-detected write appends one row with `{ts, session_id, host, pid, tool_name, target_kind ("watched-path" | "git-mutation"), target, action ("promote" | "refresh" | "conflict" | "legacy-skip" | "no-claim-skip"), reason, routine_version}`. Idle-demote events from Stop add rows with `{ts, session_id, action: "idle-demote", idle_seconds_observed, idle_seconds_threshold, routine_version}`. The ledger is the regulator-presentable per-mutation evidence ledger per the F-63-01 cross-checks rule; T4 close summarises into audit-trail markdown per element 4 (compliance trace).
- **`hooks/stop.py` idle-demote (F-63-01 Layer 2).** `refresh_claim()` gains an idle-demote check: when the refreshed claim is `mode=writer` AND `writer_session_id == our session_id` AND `(now - writer_last_mutation_ts) >= writer_idle_demote_seconds`, the writer is demoted: `mode=reader`, `writer_session_id=None`, `writer_acquired_ts=None`, `writer_last_mutation_ts=None`. The top-level liveness fields (`pid`, `pid_starttime`, `boot_id`, `host`) are preserved unchanged. A row is appended to the writer-lease ledger with action `idle-demote`. New return status `refreshed-demoted` (distinct from `refreshed` for forensic clarity). The 30-minute default threshold (`DEFAULT_WRITER_IDLE_DEMOTE_SECONDS = 1800`) was set by s68 OPEN Q2 operator decision; rationale: long enough that a normal pause between ship-cycle phases (commit → audit → push) does not churn the writer, short enough to keep parallel use of the project responsive.
- **`hooks/session-end.py` unchanged behaviour (F-63-01 Layer 2).** `release_claim()` already deletes the file regardless of mode, which correctly clears both reader and writer state in one operation. Implicit-readers (sessions that coexisted without writing the file via the reader-coexist path) have no on-disk presence and their SessionEnd no-ops cleanly via the `not-owner` path. The writer-lease ledger is append-only and survives SessionEnd; ledger summarisation into audit-trail markdown is a T4-close obligation, not a hook responsibility. Version constant bumped to 1.10.0 in lockstep; no logic change.

## 1.1.0 — Initial public release

First release as an open-source Claude Code plugin under dual GPL-3.0 (code) + CC BY-SA 4.0 (content) licensing. The plugin began life as a private internal tool; the public version represents the abstracted methodology shape, with operator-specific worked examples and reference instances kept on the operator's local machine as a private add-on layer.

What ships:

- **Five methodology slices** in `methodology-content/T0..T4.md`. Cumulative (T4 inherits T0+T1+T2+T3+T4 content). Slice for the auto-detected tier is injected as `additionalContext` at every SessionStart.
- **SessionStart hook** (`hooks/session-start.py`). Walks up to the nearest `.git/` (capped at 6 levels), scores Scope (S0..S3) and Criticality (C0..C2) from file-presence + keyword-scan signals, looks up the (S, C) -> T matrix in `detection-rules.json`, applies override precedence, injects the matching slice. Pure stdlib, never throws, fail-safe on any error.
- **UserPromptSubmit hook** (`hooks/user-prompt-submit.py`). Emits the elapsed-time clock-tag for the session-health heartbeat (T2+ rule); auto-advances LAST_HEARTBEAT on OVERDUE-2X as a layered fail-safe per D-MET-41.
- **PostToolUse hook** (`hooks/post-tool-use.py`). Fires after every tool call to surface OVERDUE / OVERDUE-2X clock-tags during long autonomous-work windows where no UserPromptSubmit fires (closes the autonomous-work heartbeat-silence gap surfaced at [EXAMPLE-PROJ] session 33). Rate-limited to once per 60 seconds. Tier-aware (T2+ only).
- **Stop hook** (`hooks/stop.py`). Greps the assistant transcript for the heartbeat-fired sentinel and advances the LAST_HEARTBEAT anchor (layered fail-safe so silent skipped heartbeats are caught).
- **Slash commands** in `commands/`: `/vc-roe:tier`, `/vc-roe:raise-tier`, `/vc-roe:lower-tier`, `/vc-roe:audit-pass`. Tier display + override + audit-pass declaration.
- **Detection rules** in `detection-rules.json`: regulatory-keyword list, scope-signal file-presence list, scope size signals, criticality path signals, locked (S, C) -> T matrix.
- **Helper scripts** in `bin/`: `anchor-rewrite.sh` (heartbeat anchor manipulation), `sync-user-aliases.sh` (idempotent re-copy of slash-command files to `~/.claude/commands/` so unqualified `/tier` works alongside namespaced `/vc-roe:tier`), `publish-audit.sh` (pre-publication leak scan against operator-private patterns).
- **Validation runner** (`test-detection.py`). Spins up synthetic project fixtures under a temp dir and exercises the SessionStart hook against each, checking the inferred tier matches expectation. Fully reproducible across machines.
- **Install scripts** (`install.sh` for Linux/macOS, `install.ps1` for Windows). One-liner curl-bash + iwr-iex installers that add the marketplace and install the plugin.

Override precedence (closer-file-wins):

1. Live `/vc-roe:tier T<N>` slash command in current turn.
2. `tier: T<N>` line in any CLAUDE.md from cwd up to project_root.
3. `.claude/methodology.json` `{ "tier": "T<N>" }` at project_root.
4. `CLAUDE_TIER` environment variable.
5. Auto-detected (S, C) -> matrix lookup.
6. Default T0.

Auto-detection caps at T3. T4 is reached only via `tier: T4` sentinel in CLAUDE.md (persistent) or live `/vc-roe:tier T4` (one-session). Tier inflation alienates operators more than tier deflation misses regulatory evidence; the cap is deliberate.

Close every Claude Code window/process, then reopen, to pick up an upgrade cleanly.
